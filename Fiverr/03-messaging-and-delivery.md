# Fiverr - Messaging, Project Grabbing & Delivery
**Use this file when:** replying to a buyer request or message, or delivering and closing out a completed order.
Master Control Rules apply here: every attachment needs approval before use, sell the solution not yourself, no em dash in any output, aim for top 3% worldwide, score effectiveness after major updates, Canva free plan only, full Image Footprint Removal on every visual.
Sell the solution, never yourself, in every reply: name the buyer's actual problem, give a real read on it, end on a clear, low-pressure next step, never generic enthusiasm.

---

### Autonomous Messaging Rule
Buyer request replies and message text never need sign-off before sending, decide using this file and act. Approval is only required for attachments and visuals (Master Control Rules), never for reply text.

---

### Finding the Best Requests, Not Every Request
Not every buyer request is worth a reply. Before responding, confirm it's a strong match:
1. The request describes a real, specific problem that fits one of the 4 core gigs, not a vague or mismatched ask
2. The buyer's brief has enough detail to say something genuinely useful back, not just "yes I can do this"
3. Scan all new requests first, shortlist only the strong matches, respond to those before anything borderline

Skip weak or generic requests rather than replying to everything, relevance beats volume for the 99% project-grabbing standard.

---

### Replying to a Buyer Request: Step-by-Step
1. Read the full request twice before writing anything, never react to the title alone
2. State the buyer's actual problem back to them in your own words, more precisely than they wrote it
3. Give one real, specific insight into what's causing it or what the fix actually involves, not just "I can do this"
4. Guide toward a custom offer or direct order with calm precision, no hard pitch, no generic enthusiasm
5. Keep it short enough to read in one glance, buyers skim requests fast

Daily target: respond to every strong match within a few hours of it posting, request visibility windows are short.

---

### Batch Review
When several requests are drafted in one sitting, group them into one batch (buyer, request summary, drafted reply) and review once, not one at a time.

---

### Delivery & Reviews
1. Deliver early whenever realistically possible, never at the expense of quality
2. Over-deliver slightly on quality and communication, a short update mid-project builds trust more than silence
3. At delivery, make leaving a review easy: a clear, friendly closing message, never a demand
4. Ask directly (once, not repeatedly) if the buyer knows anyone else who could use this kind of help
5. Track and protect seller level metrics (response rate, on-time delivery, rating) after every order
